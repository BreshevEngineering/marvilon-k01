# Marvilon Drawing Candidate Lifecycle v1

Status: CONTROLLED OPERATIONAL METHOD
Date: 2026-09-15
Parent: `MARVILON_DRAWING_SYSTEM_V1.md`

## Purpose

Close the missing bridge between deterministic semantic authoring and the human visual last mile without losing provenance.

A candidate is one immutable engineering branch with four layers:

`generated -> manual_finish -> placement_capture -> rebuild`

The generated semantic drawing is never overwritten by manual layout work.

## Canonical candidate structure

```text
<drawing output root>\drawing_system_v1_<timestamp>\
    candidate_manifest.json
    generated\
        <drawing_id>.SLDDRW
        <drawing_id>.PDF
        <drawing_id>.BMP
    manual_finish\
        <drawing_id>_ISO_FINISH.SLDDRW
        <drawing_id>_ISO_FINISH.PDF
    evidence\
        semantic_report.txt
        placement_profile.json
        placement_capture_report.txt
```

`generated` is automation-owned. `manual_finish` is human-controlled presentation only. `evidence` is machine-readable proof.

## State machine

1. `GENERATED` — semantic authoring has produced the candidate and a manifest.
2. `MANUAL_FINISH_PREPARED` — generated drawing copied to `manual_finish`; engineer may move views/annotations and route leaders only.
3. `MANUAL_FINISH_IMPORTED` — an externally finished drawing was imported into the candidate.
4. `PLACEMENT_CAPTURED` — semantic annotation/view coordinates were captured to a controlled placement profile.
5. next rebuild consumes the controlled placement profile automatically.
6. D7 semantic QA + D8 visual QA are still required before D9 promotion.

No lifecycle state implies product release.

## Semantic identity rule

Drawing System v1 assigns stable annotation names with prefix `K01DS_` to API-authored dimensions, datums, GTols, TEDs and controlled notes.

Examples:

- `K01DS_D003-C06-SIZE`
- `K01DS_DATUM_D`
- `K01DS_D003-C09-POS`

The placement capture tool resolves by these semantic names, not by screen order or nearest text.

Missing or duplicate semantic names = HOLD.

## Placement profile

Controlled path:

`control\drawings\placement\<drawing_id>_PLACEMENT_CURRENT.json`

It stores:

- view positions and scale;
- named annotation X/Y positions;
- source drawing identity/evidence.

On the next build, the generic engine uses this profile instead of the raw placement seed in the drawing spec. Product values, datum order, fit classes and GPS semantics still come only from Product Definition / drawing spec.

## Manual boundary

Allowed during `manual_finish`:

- move views;
- move annotations;
- route leaders;
- remove collisions;
- improve white space/readability;
- edit template-only administrative text when controlled upstream metadata is not yet connected.

Not allowed:

- change dimensions/tolerances;
- change datum identity/order;
- add/remove GPS modifiers;
- change material/fit/thread specification;
- invent values for OPEN items.

If a semantic change is required, return upstream to EDR/Product Definition and rebuild.

## D006 exemplar registration

Legacy hand-finished D006 may be registered as a historical Drawing System v1 exemplar without pretending it was generated by the generic engine. The candidate manifest marks `legacy_exemplar=true`; generated folder stays empty unless a generic rebuild is later produced.

## Validation criterion

Drawing System v1 placement loop is validated when:

1. D003 is rebuilt into canonical candidate folders;
2. `manual_finish` is prepared and visually adjusted;
3. placement capture returns full named-annotation coverage;
4. a subsequent rebuild applies the captured placement profile;
5. semantic output remains unchanged and only layout is reproduced.

## Current capture scope

Placement v1 captures and replays view positions/scales and semantic annotation X/Y positions. It does **not** yet capture leader elbow/jog geometry or perform automatic collision resolution. Those are separate presentation capabilities and shall not be reported as proven until a dedicated implementation and runtime test exists.

The round-trip gate is not complete until a manually adjusted D003 is captured and a new build reproduces the placement while preserving the semantic fingerprint.
