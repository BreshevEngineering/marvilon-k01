# K01 Temporal Authority Policy v1

Status: CONTROLLED PROJECT POLICY
Scope: all files or reports whose names contain `CURRENT`, all new-chat navigation, Center current-state projection, and AI handoff generation.

## 1. Problem being solved

`CURRENT` is not a timestamp and is not authority by itself.

K01 historically accumulated multiple `*_CURRENT` files from different engineering moments. A handoff could therefore be complete by file-presence while still being temporally incoherent. The project must never use "newest file wins" and must never infer current engineering state from a filename alone.

## 2. Four classes of CURRENT

### STATE_CURRENT
Global navigation/session state. Must be generated by one reducer and carry the same `state_epoch`.

Examples:
- Goal Lock
- Current Session Manifest
- Next Actions
- START_HERE
- Session Close
- Resume/current-state navigation

These files may never be hand-maintained independently.

### DOMAIN_CURRENT
Current state inside one engineering domain. It may be older than the global session epoch if its upstream inputs did not change, but it must not drive global navigation unless explicitly selected by the Session Manifest / Authority Map.

Examples:
- Product Definition readiness
- BOM projections
- analysis reports
- inspection records

### DERIVED_CURRENT
Projection/readback/UI evidence. It is not upstream engineering authority and must carry source identity/fingerprint or an explicit freshness state.

Examples:
- Center state
- drawing visual QA
- dashboards

### LEGACY_CURRENT
A file whose name says CURRENT but whose workflow has been superseded. It is forbidden as first-read/navigation context. It must be archived, replaced by a generated pointer/entry page, or explicitly marked in `K01_CURRENT_REGISTRY_v1.json`.

## 3. State Epoch

All `STATE_CURRENT` files share a deterministic state epoch:

`K01-SE-<source_fingerprint_prefix>`

The epoch is computed from the controlled sources that define current session state (Goal Lock content excluding reducer metadata, current checkpoint, current EDR decision set, Product Definition readiness, release-gap register, release requirements, seal baseline, and current D006 authoring method).

If those sources do not change, rerunning the reducer produces the same epoch.

## 4. Precedence

For "where are we / what is next":
1. `control/state/K01_STATE_EPOCH_CURRENT.json`
2. `control/project/K01_CURRENT_SESSION_MANIFEST.json`
3. `reports/control/K01_SESSION_CLOSE_CURRENT.md`
4. `reports/control/K01_START_HERE.md`
5. other navigation projections

For technical engineering values:
1. domain engineering authority declared by Authority Map / EDR / CAD / requirement / evidence;
2. compiled Product Definition and derived verification;
3. navigation summaries;
4. chat memory.

A state manifest can supersede an old navigation summary, but cannot supersede an engineering value in its domain authority.

## 5. Handoff rule

`run.cmd handoff` must:
1. refresh controlled current-state views;
2. run temporal-coherence guard;
3. fail closed if temporal coherence is HOLD;
4. only then build the handoff.

File-presence completeness is insufficient.

## 6. Center rule

Center reads the Current Session Manifest / temporal guard for global state. Domain reports remain domain evidence. Center never chooses between conflicting `*_CURRENT` files by mtime.

## 7. New-chat rule

The new chat reads:
1. State Epoch;
2. Current Session Manifest;
3. Session Close;
4. START_HERE;
5. only the active engineering authorities listed by the manifest.

Do not full-scan all `*_CURRENT` files as peer state sources.

## 8. Stale / superseded handling

- Historical content is preserved.
- Superseded navigation is moved to `archive/superseded/<date>/temporal_precedence/` when practical.
- A still-needed legacy/domain file may remain in place, but the Current Registry must mark it non-global and it must not precede State Epoch / Manifest in any first-read list.
- Derived file staleness is explicit: `FRESH`, `STALE_REVIEW`, or `INVALIDATED`.

## 9. Three independent axes

Never collapse these:
- ENGINEERING STATE: OPEN / CANDIDATE / CLOSED
- AUTHORITY AVAILABILITY: PRESENT / MISSING / EXTERNAL
- DOWNSTREAM FRESHNESS: FRESH / STALE_REVIEW / INVALIDATED

A CLOSED decision with a missing transport copy is not an OPEN engineering decision.

## 10. Anti-loop

If temporal inconsistency is detected, repair the reducer/registry/pointer once. Do not create a new parallel state system.
